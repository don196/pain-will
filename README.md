# Полигон подземелья — «Боль и Воля»

Тестовое поле боевой системы для тёмной фэнтези-НРИ (ориентиры — Fear & Hunger и Darkest Dungeon). На гексовом поле герои дерутся с болванчиками, а правила проверяются руками и тысячами симулированных боёв.

**Сайт:** https://don196.github.io/pain-will/ — обновляется сам после каждого изменения в `main`.

Сайт — одна статическая страница без сервера. Настройки правил и правки бойцов хранятся в браузере каждого игрока.

## Как устроен репозиторий

| Путь | Что там |
|---|---|
| `src/core.html` | Ядро: правила, поле, ИИ, данные бойцов и оружия, старый интерфейс. Почти все правки игры — здесь. |
| `src/ui2/` | Интерфейс 2: панели, карточка бойца, список действий. |
| `src/ui3/` | Интерфейс 3: поле, токены, контекстное меню. |
| `build/build.py` | Сборка ядра и двух слоёв интерфейса в `dist/index.html`. |
| `sim/sim.js` | Симулятор: исполняет ядро без браузера, обе стороны ведёт ИИ. |
| `sim/run.mjs` | Таблица баланса: сценарии × режимы здоровья. |
| `tests/smoke.mjs` | Проверки в браузере: страница открывается, Боль, «на пороге», «без сознания», перевязка, «Привести в чувство», переключение на HP, ход ИИ; компьютер и телефон. |
| `.github/workflows/deploy.yml` | Сборка, проверки, баланс и выкладка на GitHub Pages. |

Разделы ядра помечены заголовками вида `/* ================= БОЛЬ ВМЕСТО HP ================= */`:

- **Действия** и **шаблоны бойцов** — старые герои; данные системы 2.0 (Конрад, Хельга, Вальтер, болванчики, сценарии) лежат в разделе **Боевая система 2.0**.
- **Настройки (спорные правила)** — значения по умолчанию для переключателей из окна «Правила».
- **Разрешение атаки** — бросок, степень, урон или Боль, раны.
- **Ходы и раунды**, **ИИ**.
- **3 ОД**, **Боль вместо HP** — новые механики.

## Запуск у себя

Нужны Python 3 и Node.js 20+.

```bash
npm ci                 # один раз: ставит Playwright для проверок
npm run build          # собирает dist/index.html
npm run serve          # http://localhost:8000
```

Можно и просто открыть `dist/index.html` в браузере.

## Как вносить изменения

1. Заведи ветку, поправь файлы в `src/`.
2. Проверь у себя:
   ```bash
   npm run build
   npx playwright install chromium   # один раз
   npm test
   npm run sim                       # таблица баланса, по 200 боёв на строку
   ```
3. Открой пулл-реквест. GitHub соберёт страницу, прогонит проверки и положит таблицу баланса во вкладку **Actions → запуск → Summary**: сразу видно, сдвинула ли правка проценты побед.
4. После слияния в `main` сайт обновится примерно через пару минут.

**Про сборку.** Слои интерфейса вставляются заменой точных кусков ядра. Если поменять в ядре кусок, на который опирается сборка, она остановится и покажет, какой фрагмент не нашёлся. Тогда поправь соответствующую замену в `build/build.py`.

## Симуляции

```bash
npm run sim -- --n 600                         # точнее, дольше
npm run sim -- --scn dummies6 --modes pain     # один сценарий, один режим
node sim/sim.js '{"scn":"dummies","n":300,"set":{"pain":false}}'   # сырой JSON
```

В `set` передаются настройки из окна «Правила» (например, `pain`, `ap3`, `dexMode`, `spellDC`), в `over` — правки бойцов и действий: `{"T":{"dummy":{"mm":4}},"A":{"club":{"pcls":"med"}}}`.

## Что дальше

- Разрезать ядро на модули: правила отдельно от интерфейса, данные бойцов и оружия — отдельными таблицами. Тогда параллельные правки не будут конфликтовать.
- Убрать режимы, которые больше не нужны (2 ОД, система от 12.11, старые герои).
- Перевести на TypeScript: проверка типов ловит ошибки, когда одна механика забывает про другую.

Текст правил ведётся отдельно, у автора.
